Este trabalho implementa e compara dois algoritmos de eleição de líder em um anel unidirecional (VRing): o Algoritmo 1 (Chang-Roberts, baseado em candidatos) e o Algoritmo 2 (aleatorizado / Randomized Leader Election).

Algoritmo 1: Eleição de Líder Chang-Roberts no Anel

1. O algoritmo de Chang-Roberts

O algoritmo de Chang-Roberts elege um líder entre N processos organizados em um anel unidirecional (cada processo só envia mensagens ao seu sucessor). Parte dos processos são candidatos a líder; o critério de eleição adotado é o maior identificador.

Cada processo mantém uma variável local Lider:

  • Um candidato inicializa Lider com o próprio id;
  • Um não-candidato inicializa Lider = -1 (não conhece líder ainda).

As regras de processamento de uma mensagem que anuncia um candidato de id idCand:

  • Se idCand > Lider: atualiza Lider = idCand e repassa a mensagem ao sucessor;
  • Se idCand ≤ Lider: descarta a mensagem (ela não circula mais);
  • Se a mensagem que chega é a própria mensagem do processo (ela deu a volta completa no anel), então ele é o líder eleito — todos os processos já a receberam.

Como apenas a mensagem do maior id nunca é descartada, somente ela completa a volta no anel e retorna ao remetente — garantindo que exatamente um líder (o de maior id) seja eleito.

Ilustração do anel (N = 7)

        0 → 1 → 2 → 3
        ↑           ↓
        6 ← 5 ← ← ← 4

  Mensagem circula sempre no sentido i → (i+1) mod N

2. Modelagem no SMPL

O SMPL é um simulador a eventos discretos: o tempo avança de evento em evento. Modelamos a eleição com dois eventos:

  • INICIA — um candidato dispara a eleição enviando sua própria mensagem ao sucessor;
  • MENSAGEM — a chegada de uma mensagem de eleição a um processo.

Cada salto de mensagem entre vizinhos é agendado com schedule() e consome TEMPO_MSG = 1.0 unidade de tempo, simulando a latência de transmissão.

Decisão-chave: codificar o payload no token

O schedule() do SMPL transporta apenas um inteiro (o token), mas uma mensagem precisa carregar duas informações: o destino e o id do candidato anunciado. A solução foi empacotar os dois em um único inteiro, tratando-o como um número na base N: 

  Codificação (no envio):   token = destino * N + idCandidato
  Decodificação (na chegada): destino = token / N
                              idCandidato = token % N

Como idCandidato sempre está em 0..N-1, ele nunca transborda para o "dígito" do destino, então a separação por divisão e resto é sempre exata. Exemplo com N=7: o candidato 4 enviando ao sucessor 5 produz token = 5*7 + 4 = 39; o processo 5 decodifica 39/7 = 5 (destino) e 39%7 = 4 (candidato).

Outras decisões

  • Seleção de candidatos por cenário: o segundo argumento da linha de comando escolhe o cenário (1 = único, 2 = aleatório, 3 = todos). No cenário aleatório, cada processo é candidato com 50% de chance (via ranf() do SMPL), garantindo ao menos um candidato.
  • Detecção de término: o laço principal roda enquanto liderEleito == -1. Como a mensagem do maior id sempre retorna ao remetente, a eleição sempre termina — não é necessário um limite de tempo artificial.
  • Contagem de mensagens: a métrica totalMensagens é incrementada a cada schedule() de uma MENSAGEM (envio inicial ou repasse). Mensagens descartadas não geram novo envio, logo não são contadas.
  • Versão sem falhas: esta implementação assume o anel confiável (sem processos falhos). As facilities do SMPL são mantidas na estrutura como gancho para uma futura versão tolerante a falhas, mas não são usadas aqui.

3. Cenários de teste e métricas

Todos os testes foram executados com N = 7 processos. As métricas exigidas pelo enunciado — líder eleito, número de mensagens e tempo de simulação do SMPL — estão resumidas abaixo, e os logs completos estão linkados.

Cenário Candidatos Líder eleito Mensagens Tempo SMPL Log
1 — único candidato 0 0 7 7.0 log
2 — aleatórios 1, 2, 3, 5 5 11 7.0 log
3 — todos candidatos 0..6 6 13 7.0 log

Análise

  • Cenário 1: com um único candidato, a mensagem simplesmente dá a volta completa no anel (N saltos), totalizando N = 7 mensagens. É o caso trivial.
  • Cenário 2: os candidatos de id menor (1 e 2) são descartados logo no primeiro salto, ao chegarem em vizinhos de id maior. Apenas a mensagem do maior id (5) completa a volta.
  • Cenário 3: com todos candidatos, no primeiro salto cada mensagem de id menor é imediatamente absorvida pelo vizinho de id maior, restando apenas a do maior id (6) para circular. O total observado foi de 2N − 1 = 13 mensagens para este arranjo.

Por que o tempo é sempre N (= 7)

O tempo de simulação é idêntico (7.0) nos três casos, e isso não é coincidência. O instante em que a eleição termina é determinado por um único fator: o momento em que a mensagem do candidato de maior id completa uma volta inteira no anel e retorna ao seu remetente. Essa volta tem sempre exatamente N saltos, pois a mensagem vencedora visita todos os N processos e volta — independentemente de quem vence ou de quantos candidatos existem.

Como todos os candidatos lançam sua candidatura no mesmo instante (tempo 0) e cada salto custa TEMPO_MSG = 1.0, o tempo total é sempre: 

  tempo total = N saltos × TEMPO_MSG = 7 × 1.0 = 7.0

Note a independência entre tempo e número de mensagens: acrescentar candidatos aumenta o tráfego (7, 11 e 13 mensagens nos três cenários), mas não a latência (sempre 7.0), porque as mensagens viajam em paralelo, no mesmo ritmo, e os candidatos perdedores são absorvidos sem segurar o vencedor. O tempo só mudaria se N ou TEMPO_MSG mudassem — com outro N, o tempo seria exatamente esse novo N.

Em termos de número de mensagens, o algoritmo é O(N) no melhor caso e O(N²) no pior caso (quando os ids estão dispostos em ordem decrescente ao redor do anel, fazendo cada mensagem viajar muitos saltos antes de ser descartada); o caso médio é O(N log N).

Algoritmo 2: Eleição de Líder Aleatorizada (Randomized) no Anel

1. Ideia geral do algoritmo aleatorizado

O Algoritmo Aleatorizado de Eleição de Líder no Anel (VRing) utiliza rodadas sucessivas para reduzir o conjunto de candidatos até sobrar apenas um líder. A cada rodada, cada processo candidato sorteia um bit aleatório:

  • bit = 1 → o processo continua na disputa e torna-se candidato da rodada;
  • bit = 0 → o processo desiste da rodada e permanece apenas encaminhando mensagens.

Cada processo informa ao anel seu id e o bit sorteado na rodada atual. Quando a mensagem completa o anel, todos os processos daquela rodada conhecem os bits dos participantes restantes. O algoritmo termina quando restar exatamente um processo com bit = 1; esse processo é declarado líder.

2. Estratégia de implementação

Para representar o anel, cada processo conhece apenas o seu sucessor: proximoProcesso(i, N) = (i + 1) mod N. Assim, cada mensagem sempre avança um único passo no sentido do anel, até completar uma volta.

O estado local de cada processo é mantido em uma estrutura com as seguintes informações:

  • id: identificador do processo no SMPL;
  • bit: bit atual sorteado na rodada;
  • lider: líder conhecido até o momento;
  • rodada: número da rodada em andamento;
  • candidatos: lista dos processos que permaneceram na disputa;
  • recebeuRound: controle dos processos já vistos nesta rodada.

Codificação da mensagem

Como o schedule() do SMPL transporta apenas um inteiro como token, foi necessário empacotar as informações da mensagem em um único valor. Para isso, o token foi usado como um "registro compacto", contendo os campos necessários para reconstruir a mensagem na chegada. 

token = ((src * N) + dst) * 2 + bit

Decodificação:
  bit = token % 2
  token = token / 2
  dst = token % N
  src = token / N

Essa representação permite carregar, ao mesmo tempo, a origem, o destino e o bit sorteado na rodada, sem alterar o núcleo do SMPL.

3. Funcionamento por rodadas

O algoritmo foi organizado em três fases principais:

  1. Fechamento da rodada atual e início de uma nova: Na primeira rodada, pula-se direto ao início de uma rodada, onde todo processo com bit 1 sorteia um bit novo aleatório e inicia-se a circulação das mensagens. No fechamento da rodada, os processos verificam quantos candidatos ainda possuem o bit 1. Se houver mais de um, uma nova rodada começa; se houver apenas um, a eleição termina e o líder é eleito.
  2. Circulação da mensagem: cada processo recebe informações e as encaminha aos sucessores, carregando o id e o bit da rodada. Quando um processo recebe mensagens de todos os outros, termina-se a rodada.

Na primeira rodada, todos os N processos participam. A partir da segunda rodada, somente os processos cujo bit vale 1 continuam concorrendo. Isso faz com que o número de candidatos diminua rapidamente com o avanço das rodadas.

Critério de término

A eleição termina quando o número de candidatos ativos é igual a 1. Nesse momento, o processo restante é anunciado como líder. Caso todos os bits de uma rodada sejam zero, a rodada é repetida com nova amostragem, garantindo progresso probabilístico.

4. Métricas coletadas

O relatório pede três resultados principais para cada execução:

  • Líder eleito: qual processo venceu a eleição;
  • Quantidade de mensagens: número total de transmissões realizadas até o fim;
  • Tempo SMPL: tempo lógico total consumido pela simulação.

Para contabilizar mensagens, o simulador incrementa um contador sempre que agenda uma nova mensagem de eleição. O tempo final é obtido diretamente por time() no instante em que a eleição termina.

Em uma implementação como esta, o tempo do SMPL cresce de acordo com o número de saltos do anel necessários para propagar as rodadas. Já o número de mensagens depende fortemente de quantos processos continuam com bit = 1 a cada rodada.

6. Como executar

A aplicação foi compilada junto com o SMPL e executada informando o número de processos do anel. Em cada execução, o programa imprime os eventos principais, o líder eleito, a quantidade total de mensagens e o tempo total da simulação. 

  make
  ./tempo <N>

7. Conclusão

O algoritmo aleatorizado mostra uma forma simples e elegante de resolver a eleição de líder em anel quando não se deseja depender de um critério determinístico como o maior identificador. A cada rodada, a competição é reduzida por sorteio, até que apenas um processo permaneça ativo. Quando, por chance, nenhum processo está mais ativo, reinicia-se a escolha até que se reduza a apenas um processo.
